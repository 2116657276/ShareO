# ShareO 当前执行计划

> 本文件只维护执行顺序、阶段门禁和暂停条件；实时状态以 [`TASK.md`](../TASK.md) 为准。

## 主线

```text
文档治理
→ 本机后端收口
→ 后端自动验收
→ Go Template 前端补齐与重构
→ 本机自动回归
→ 用户人工测试与验收
→ Docker/Compose 最终打包与发布复核
```

当前不执行 Docker/Compose、浏览器或数据库重置。日常开发和前端开发使用宿主机 Go/Python、Homebrew MySQL/Redis/MinIO、本地 Qdrant 和已有模型缓存；机器评测只在门禁复核时运行。人工验收通过后才恢复 Docker 打包。远程同步不属于日常开发步骤，只有用户明确要求时才执行，并先检查远程是否可安全快进。

`resources/static/pictures/` 构建 47 条本机专用帖子。该入口软删除当前 31 条旧帖子，保留
MinIO 历史对象，再通过现有 `index_post` Redis stream、AI worker 和 Qdrant 完成图片与正文

检索参数或质量阈值；扩展语料上的人工体验结果不能冒充冻结评测结果。

## 阶段 1：本机后端收口

### API 契约

- 对照 `internal/router/router.go`、`ai-service/app/main.py` 和 `docs/reference/api.md`，核对路径、方法、认证、参数、分页、状态码、错误结构和可见性。
- 保持公开语义搜图 `GET /api/v1/search/images`；AI 内部使用 `POST /v1/search/images`、`POST /v1/rag/answer`；Agent 继续由聊天消息 `ai_mode=agent` 触发。
- 不新增公开 RAG/Agent API，不因浏览器直接打开 JSON 的工具限制改变路由。

### 自动化覆盖

- 扩展本机 API 测试，覆盖认证、权限、帖子、审核、搜索、聊天、默认 RAG、显式 Agent、内部 Token、重复投递、资源不存在和依赖不可用路径。
- 通过现有单元测试、真实 MySQL/Redis/Qdrant 集成、readiness、故障语义和机器评测验证跨服务边界。
- 不直接改写数据库、Redis、MinIO 或 Qdrant 来制造测试成功；测试数据只清理本轮创建内容。

### 后端退出门禁

- `make check`、`go test -race ./...`、本机 API、真实集成、`make local-doctor`、`make test-local-stack`、`make warm-ai` 全部通过。
- RAG 40/30 机器门禁保持通过。
- 当前代码重新完成一次 36 条真实 DeepSeek Agent 机器评测：必需工具选择率 ≥ 0.85，来源、引用、安全、失败、预算和 P95 门禁全部通过。
- 历史 dirty 报告不能替代当前代码的有效复评；当前代码通过后进入前端阶段，前端阶段不修改 Prompt、数据集、检索参数和质量阈值。
- 不修改 Prompt、冻结数据集和质量阈值；如确实需要调整，暂停并等待用户批准。

## 阶段 2：Go Template 前端补齐与重构

后端门禁通过后，继续使用现有 Go Template、原生 CSS 和 JavaScript，不迁移 Vue/React，不引入 Node 构建链。

- 新增 `/search/images` 页面，调用现有 `/api/v1/search/images`，实现中文输入校验、加载、空结果、503、结果卡片、作者/描述展示和帖子跳转。
- 统一登录注册、Feed、搜索、帖子发布/编辑/详情、用户、通知、私聊、RAG/Agent、管理员和错误页面的布局、导航、表单、按钮、卡片和反馈状态。
- 补齐响应式布局、键盘可用性、基本语义标签、服务不可用和权限失败提示；不展示内部 Token、工具原始参数或内部服务地址。
- 保留已有路由和 API 契约；页面级验证使用模板渲染、Handler、静态契约和本机 API 测试，不执行浏览器操作。

## 阶段 3：人工验收前自动回归

- 运行本机 Go/Python 单测、静态检查、race、API、集成、readiness、RAG 和 Agent 机器门禁。
- 生成最终人工测试清单，覆盖登录、社区、审核、搜图、私聊、WebSocket、RAG、Agent、引用、权限和错误状态。
- 新 Agent 机器报告通过后生成验收材料；历史 30 条评分保留为历史证据，最终从新报告抽查 10 条答案。
- 完成 Markdown 门禁、链接检查、敏感信息扫描、未跟踪大文件检查和 `git diff --check`。
- 在该阶段结束前不运行浏览器，不启动 Docker/Compose。

## 阶段 4：用户人工测试与验收

由用户一次性执行最终人工验收：

1. 注册、登录、Feed、发布、编辑、审核、点赞、评论、关注和通知。
2. 独立语义搜图的正常、空结果和 AI/Qdrant 不可用状态。
3. 普通私聊、WebSocket 实时下行、断线恢复和消息顺序。
4. 默认 RAG、显式 Agent、步骤卡片、引用详情和引用跳转。
5. 管理员权限、普通用户越权、响应式布局、表单校验和错误提示。
6. 从新 Agent 报告抽查 10 条，核对正确性、完整性、工具选择、引用和表达自然度。

人工发现问题时返回后端或前端阶段修复并重新执行对应自动门禁。用户未明确确认通过前，不进入 Docker 阶段。

- 修正构建上下文，排除 `qdrant/target`、`.cache`、Python 虚拟环境、模型、个人照片、日志、PID 和运行数据。
- 使用代理和本地缓存完成源码镜像构建，不用已有业务镜像冒充源码冷启动。
- 执行全新 Compose 冷启动、两次幂等 `demo-seed`、六服务健康、图片/RAG/Agent readiness、对象与索引对账。
- 运行图片、Bot、Agent E2E、五类故障恢复矩阵和最终 40/30 及 Agent 质量复核。
- 归档脱敏证据，最后更新 README、阶段状态、简历表述和发布文档。
