# ADR-007：真实 Provider 与质量评测策略

- 日期：2026-07-23
- 状态：已接受

## 背景

项目需要真实 LLM 证据，但把 DeepSeek、Ollama、4060 和多 Provider 成本对比全部设为门禁会引入不必要的网络、硬件和评测负担。

## 决定

- OpenAI-compatible 接口保持通用，DeepSeek 是当前策略中唯一强制真实验收 Provider。
- mock Provider 只用于确定性 E2E，不计入真实质量证据。
- Ollama 和 4060 是可选实验，不阻塞当前项目范围。
- 当前报告运行使用 38 条搜图（含 8 条 no-match）、32 条搜贴、30 条 v1 RAG 和 36 条 v1 Agent；当前代码默认的 v2 RAG/Agent 输入尚未完成三轮复评，不替代已归档指标；旧的 40 条搜图口径不再作为当前门禁。
- DeepSeek 记录端到端 P50/P95、可取得的分段耗时与超时率，不设 Provider 延迟硬阈值；本地检索保留性能门禁。

## 质量门禁

- 搜图 Recall@5 ≥ 0.70、MRR ≥ 0.55。
- RAG来源命中率 ≥ 0.80、引用可访问率100%、虚假引用0。
- RAG/Agent AI judge 平均分 ≥ 4.0/5、最低分 ≥ 3.0；分歧、低置信或确定性审计冲突的答案转人工复核，AI 评分不表述为人工评分。
- RAG/Agent 完整来源覆盖率 ≥ 0.80；Agent 必需工具选择率 ≥ 0.85，额外/禁止工具、虚假引用和注入拒答失败均为 0。
- 图片搜索预热后MPS P95 ≤ 2秒、CPU P95 ≤ 4秒；RAG本地检索P95 ≤ 2秒。

## 后果

评测报告必须记录数据集、模型、Prompt、日期、设备和网络环境。API Key不得进入仓库、日志、截图或报告。供应商网络波动不会单独阻塞发布，但超时率必须透明记录。

当前证据边界：Final Freeze 已记录实际 Provider、模型、Prompt SHA、数据集 SHA、Git/dirty 状态和可取得的分段耗时；当前仍未完成干净提交复评，部分阶段因没有可靠样本标记为 `unavailable`。因此本 ADR 的门禁口径已落地，但不能把 dirty 本机结果写成发布复现结果。
